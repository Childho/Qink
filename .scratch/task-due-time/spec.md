# 任务截止时间（due time）· 设计共识

> 本文档是 2026-09-27 拷问会话（grilling）的最终共识，经用户逐题确认。
> 术语以根目录 `CONTEXT.md` 为准；主规格见 `.scratch/qink-phase1/spec.md`。

## 一句话

给「怕忘时间点」的任务一个**可选**的截止时间：最后 24 小时自动置顶变红，逾期后悬浮球裂开一道缝常亮提醒，直到完成 / 改期 / 删除。没设时间的任务一个字节都不变。

## 动因（用户原话的提炼）

有些工作需要其他部门配合、有明确交付时间，无法自主控制，怕忘。**不是所有任务都需要设定完成时间**——时间字段可选，纯按需。

## 哲学合规声明（为什么这不算破坏设计理念）

- 提醒靠**看见**，不靠打断：无系统通知、无弹窗、无闪烁、无声音。产品身份仍是安静的桌面贴纸。
- 「裂缝」是招牌视觉母语的延伸：**完成 = 碎掉消失；逾期 = 裂着不消失**。同一个视觉词根表达两个时间语义。
- 高频动作零控件不变：设定时间是低频动作，藏右键抽屉（与改写/删除同族）。
- 对称分工：**任务有时间压力，目标没有**——目标区不加周期倒计时，保持完全安静。

## 数据

- `Task` 增加可选字段 `dueAt?: string`（ISO 本地时间字符串）。旧数据无此字段 = 未设时间，浅合并天然兼容，`version` 不动（`pinned` 先例）。
- **粒度规则（用户定的）**：今天的任务 → 时刻（精确到分，存 `2026-09-27T15:00:00`）；明天及以后 → 日期（存当日 0 点 `2026-09-30T00:00:00`，语义 = 该日结束前完成都不算逾期）。
- `ArchivedTask` 同步带 `dueAt` 存档；从档案修复时原样带回（修复回一条已逾期任务 → 立即红，信息无损）。
- 「是否紧急 / 是否逾期」**不落盘**：由 `dueAt` + 当前时间实时推导（派生式，与滚入判定同构，跨午夜重算与开机补算天然免费）。

## 判定规则（唯一事实表）

设日期任务到期日为 D，时刻任务到期时刻为 T（必为今天或过去）：

| 状态 | 日期任务 | 时刻任务 | 表现 |
|---|---|---|---|
| 安静 | 今天 < D-1 | —（无此态） | 常规/滚入色 + 淡字标注（如「9/30」） |
| 明天 | 今天 = D-1 | — | 常规/滚入色 + 淡字「明天」 |
| 紧急 | 今天 = D（最后 24h） | now < T（今天内） | **自动置顶 + 红** |
| 逾期 | 今天 > D | now ≥ T 或已跨夜 | **保持置顶 + 红 + 球裂缝** |

- 「不足 24 小时」严格成立：紧急窗口 = 最后 24 小时；**到期日当天做掉不算逾期**（到期锚点 = 到期日次日 0 点）。
- **今天的时刻任务出生即紧急**：创建即 <24h → 一落地就置顶变红。规则零特例（「设了今天时刻 = 亲口说它有时效 = 上桌」），用户已确认接受。
- 时刻任务跨夜翻篇 → 直接逾期（琥珀橙来不及出现，红接管）。
- 滚入的日期任务（如明天到期、今晚滚入）：琥珀橙 +「明天」标注——琥珀橙说它从哪来，「明天」说它要去哪，语义不打架。

## 分区与颜色

- 分区四层：**紧急（自动）> 标记（手动紫）> 滚入（琥珀橙）> 今日**。时间的紧迫是客观事实，排在用户主观意愿之上（符合「怕忘」动因）。
- 色阶优先级：**红（紧急/逾期）> 紫（标记）> 橙（滚入）> 常规**（沿「标记与滚入叠加显示紫」的既有先例升级为四级）。
- `pinned` 与紧急独立：叠加时任务进紧急区、显示红，`pinned` 字段不动（信息无损，手动标记状态还在）。
- **紧急与逾期同红，贴纸内不区分**（用户明确要求克制：不要「已逾期 N 天」文字）。区分信号 = 球裂缝（仅逾期）+ 过夜仍红必是逾期。
- 紧急区内多条按数组顺序稳定排列（与现有区内排序规则一致）。
- 完成碎裂时克隆自动带色（红色碎片，既有机制自然继承）。

## 交互

**设定 / 改期 / 取消**：右键任务 →「设定时间」（位于「改写」与「删除」之间）→ 行内输入（复用改写模式与 IME 组合守卫）：

- 接受的语法：`15` / `15:30`（今天时刻）· `9/30`、`10/2`（日期）· `明天`、`后天`
- 日期解析取**未来的最近匹配**：12 月输入 `1/5` → 明年 1/5
- 已过时刻（今天 16:00 输 `15`）→ 拒绝：不保存、输入框轻抖，可重试或 Esc
- 无法解析（如 `abc`、长句 `下周三下午`）→ 同上拒绝
- 输入态**预填当前值**，改期 = 改完提交；**清空提交 = 取消时间**
- 刻意不做自然语言长句解析：识别面越宽静默存错越容易，静默错误是信任杀手

**两形态提醒**：

- 贴纸展开：紧急/逾期任务行红色（无文字）；非紧急的带时间任务行尾淡字标注（「明天」「9/30」）
- 悬浮球收起：存在任一逾期任务 → 球面一道裂缝，**常亮不闪**；无逾期 → 无裂缝。裂缝样式为视觉自由项（实现时与 crackLines 裂纹语言同源）

**解除**：完成（碎裂入档）/ 改期（按新时间重算）/ 删除，三者任一。

## 明确不做

- 系统通知、弹窗、闪烁、声音（产品身份红线）
- 分钟级「到点闹钟」语义：时刻仅用于判定今天的紧急/逾期边界，不做整点提醒
- 目标区周期倒计时（「被天天看见」≠ 制造压力）
- 长句自然语言解析、`10月30日` 全格式（用户按推荐收窄）
- 紧急/逾期状态落盘

## 已知并接受的软肋

- **全红脱敏**：多条逾期全红 + 裂缝常亮，久了可能狼来了。接受——红是真话，全红说明真的全拖了。
- **出生即压顶**：今天时刻任务一创建就盖过手动标记。接受——规则零特例换可解释性。
- **手动标记被红盖**：pinned+紧急时紫色视觉不可见（位置和信息都在，状态真实）。
- **到期日全天红**：日期任务到期日 0 点起就红，而非最后几小时——日粒度的代价。
