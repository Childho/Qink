# ADR-0005：便签高度随内容自适应

日期：2026-09-11

## 背景

ADR-0004 为还原原型把贴纸固定为 320×540。实际使用中任务少时下方留白过多（用户反馈"空白留的太多，应该和已有任务有关联"）；字号切换、目标文字长短对高度的需求也不同，固定高与内容脱节。

## 决策

推翻 ADR-0004 中"固定 540 高"的部分，宽度 320 与四周透明边距（左56、上40、右56、下88）不变。高度改为内容决定：

- **空态最小 420px**（用户拍板：输入框下保留约三行任务的呼吸留白，仍是"一张便签"的观感）。
- 任务增删、字号切换时高度随内容伸缩，**窗口左上角锚定不动**，只有底边移动；玻璃映射按贴纸左上角计算，天然不受影响。
- 长高以工作区为上限（`maxNoteHeightFor`：工作区高 − 上边距 − 底部阴影空间），触顶后任务区内部滚动（spec"列表超出贴纸高度时内部滚动"不变）；放不下时退回最小值，位置由 clampNotePosition 兜底。
- 职责划分：CSS 用 `height:auto + min/max-height` 表达边界；渲染层上报「**内容需要的高度**」= 当前高 + 任务/目标区被上限截住的滚动溢出量，经 `qink:note-resize` 上报；主进程只负责 clamp 后 `setBounds` 同步窗口，并在触底时把位置上顶。
- **上报内容需要的高度，不能只报可见高度**：CSS 上限 `calc(100vh - 128px)` 以当前窗口为基准，若报可见高，窗口永远不长大、上限永远不放宽，形成死锁（首次验证脚本抓到：18 条任务便签卡在 422px）。内容变化由 `MutationObserver` 捕获、窗口/字号变化由 `ResizeObserver` 捕获，rAF 合帧 + 去重后上报。

## 代价

- 窗口高度变化瞬间，便签边缘与阴影可能有约一帧的轻微跳动（透明窗口 resize 与渲染层布局不同步的固有代价）；不做高度过渡动画——Windows 透明窗口动画易闪烁，先求稳。
- 启动时以最小高度建窗、渲染后立即校正，理论上有一帧跳变；因窗口 `ready-to-show` 后才显示，实际不可见。
- ADR-0004 的"原型 540 高"截图对照不再逐像素成立（宽度与排版仍一致）。

## 验证

tests/window.test.ts 覆盖最小值、换算、高度 clamp 与动态高度下的位置越界。`.scratch/adaptive-height/verify.cjs` 用真实 preload 构建 + dev 渲染层 + 内存种子数据隔离验证：18 条任务便签长到 746px、窗口 874 精确跟随、清空后缩回 420、左上角锚定不动、上报合帧去重；同方案曾抓出"只报可见高导致窗口永不长大"的死锁。
