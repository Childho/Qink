# ADR-0006：便签边缘拖拽调尺寸与双击恢复默认

日期：2026-09-11

## 背景

M13 交付高度自适应（ADR-0005）后，用户要求：鼠标移到便签边缘可以调整尺寸，双击恢复默认。内容自适应与手动尺寸需要共存且可切换。

## 决策

- **边缘热区**：#note 内贴边的透明细条（左右/底 6px、两个下角 16px，z-index 4），拖拽调整尺寸；光标形状暗示方向（ew/ns/nesw/nwse-resize）。不支持顶边调高——顶边是目标区，误触率高，且改高会破坏"位置 = 便签左上角"的语义。
- **宽度恒为手动值**：默认 320，边界 260–720，持久化 `settings.noteW`。
- **高度两档**：`settings.noteH` 为 null → 自适应（ADR-0005，上报内容期望高度）；有值 → 手动固定（拖拽设定，下限 280，任务多时内部滚动——用户选定"拖完就固定"语义）。**拿到底边即接管为手动**。
- **双击任意边缘热区**：清除 noteW/noteH，回到 320 宽 + 自适应高。双击目标限定边缘：任务文字双击已被"改写任务"占用，便签空白单击已用于打开输入行。
- **左边缘拖拽**：宽度变化时同步平移窗口 x（锚点跟随），便签左缘跟手；其余边保持窗口左上角不动。
- **同步闭环**：渲染层 rAF 合帧上报 (宽, 高, 窗口x?)，主进程 clamp 后 setBounds；高度被工作区截住时经 `qink:note-capped` 回传实际值，手动模式同步 CSS 并落盘，避免便签伸出窗外。主进程启动即按持久化尺寸建窗，重启不跳变。
- 数据格式：`settings` 新增 `noteW/noteH`（number|null，null = 默认/自适应），旧数据文件缺字段按 null 处理。

## 代价

- 手动固定高度后，任务超出部分在任务区内部滚动，不再自动长高（须双击恢复自适应）。
- 边缘热区占去贴边 6px 的单击区域（均落在原 padding 内，不遮内容）。
- 尺寸手势期间窗口 setBounds 按帧跟随，与拖动移动便签同一模式，低端机上可能有轻微滞后。

## 验证

`.scratch/adaptive-height/verify.cjs` 18 项全通过：持久化尺寸随启动应用（500×600 + 手动高度内部滚动）、底边 +80 跟随且落盘、右边缘 +80 宽度跟随且 x 锚定、左边缘 -40 宽度增且窗口左移跟手、双击清除持久化并回自适应、清空任务缩回空态 420。tests/window.test.ts 覆盖宽度边界、双模式下限、换算与位置 clamp。
