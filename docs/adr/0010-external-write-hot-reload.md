# ADR-0010：外部写入通道与热重载（AI 直写 data.json）

日期：2026-10-21

## 背景

第二阶段愿景是让外部工具（AI / 脚本 / 未来的 MCP server）直接读写 Qink 数据。数据层是纯 JSON 单文件（ADR-0001），外部写入通道天然存在，但存在一条**硬边界**：

- Qink 启动读一次 `data.json` 进内存，此后**内存是唯一权威**——每次变更防抖 300ms 落盘（ADR-0009），无任何文件监听；
- 运行中外部改文件**完全不被感知**，且下一次任何 `queueSave`（用户任意编辑、拖动窗口、退出冲刷）都会用内存态把外部写入**静默覆盖**。

所以「外部写入」若不解决感知问题，每次写入都必须退出 Qink 再重启——与「常驻便利贴」的产品本质冲突。

## 决策（2026-10-21 grilling 两轮共识，用户逐题确认）

### 1. Qink 侧：文件热重载（本 ADR 的核心增量）

`store-io.ts` 新增外部监听，主进程推送，渲染层无锁刷新：

- **监听目录而非文件**：原子写用 rename 顶替文件，Windows 上盯被顶替的旧句柄会失明；监听 `dirname(dataFile)` 并按文件名过滤（`.tmp` 天然被排除）。
- **250ms 监听防抖**：合并同一次外部原子写产生的 change/rename 连发。
- **四条防线**（顺序即语义）：
  1. 自身防抖挂起或落盘进行中（`saveTimer` / `writing`）→ **本轮放弃**——用户的未落盘编辑优先（撞车规则）；
  2. 读不出或不是 JSON 对象 → **忽略不隔离**——外部文件可能是别家写了一半，现场原地保留给启动恢复链（ADR-0009）处置；
  3. 内容与内存一致 → 跳过——**这同时天然抑制自身落盘触发的监听回环**，无需自写标志位；
  4. 校验通过 → 灌入 cache，回调推渲染层（`qink:data:external` 全量数据）。
- **渲染层只换数据源重渲染、绝不回写**：复用 `render()`（其守卫天然避开正在进行的输入/拖动/清单），不调 `persist()`——否则形成「写→看→写」回环。窗口几何（位置/形态/尺寸）是应用自身状态，外部改 `settings` 中的几何字段本次运行不生效，下次启动生效。

### 2. 外部侧：`qink-tasks` skill（`.agents/skills/qink-tasks/`）

AI 经配套脚本读写数据文件，脚本内置与 ADR-0009 同构的安全模型：形状校验不过整批拒绝、tmp+fsync+rename 原子写、主文件+AppData 备份双写、**写后延迟核验**——被 Qink 撞车顶掉则基于最新文件重试一次，仍失败如实报错（对应撞车规则的「AI 侧重试」）。破坏性操作（删除/替换清单）必须 `--yes`（对话中先向用户列影响清单）。

skill 内复刻的日期/截止时间纯函数（periodKey、dueAt 解析等）由 `tests/skill-parity.test.ts` 与 `src/shared` 源实现**逐值钉死**——改 shared 不同步 skill 会红。

### 3. 撞车规则（用户拍板）

用户未落盘编辑（300ms 防抖窗口）与外部写入同时到达时：**Qink 优先**，外部本轮被顶掉，skill 侧核验后重试。丢一次 AI 写入远好于丢用户手动编辑；实际窗口是毫秒级，装机版实测往返零失败。

## 否决的替代方案

- **skill 检测到 Qink 运行就拒绝写入**（要求用户退出再写）：零产品改动，但每次填任务都打断常驻，长期不可用；
- **skill 自动「关 Qink → 写 → 拉起」**：可自动化但贴纸每次闪断，且球形态下优雅关闭能否可靠触发退出冲刷未经验证；
- **等第二阶段 MCP 一起做**：MCP 同样需要「外部数据变化 → 界面刷新」这条管道，热重载是它的地基，先铺不亏。

## 代价与边界

- 渲染层收到外部数据时不弹任何提示（贴纸直接长出任务）——安静是产品性格；诊断留痕在 `qink.log`（`external-reload` 事件）。
- 外部写入与用户编辑在 300ms 窗口内真撞车时，外部写入可能丢一轮（重试兜底）；用户编辑**永不**被外部数据顶掉。
- 监听只在主文件目录上；备份文件变化不触发（备份不是写入口）。
- 极端环境（目录被删后重建）下 `fs.watch` 句柄失效 → 记日志停用热重载，其余功能不受影响，重启恢复。
- skill 不改 `settings`（几何/形态/置顶是应用自身状态）；`dueAt` 语义约束（非 0 点时刻只允许今天）由脚本强制，防止显示错乱。

## 验证

`tests/store.test.ts` 新增 5 例（真实临时目录+真实定时器惯例）：外部写入触发回调并灌入内存、自身落盘回环抑制、坏 JSON 忽略不隔离、防抖挂起时外部写入被顶掉且落盘为内存态、备份文件变化不触发。`tests/skill-parity.test.ts` 10 例：全年逐日周期键奇偶、dueAt 全语法域奇偶、skill 数据操作语义（去重/入档/整批拒绝/撞车检测）。**运行态实测**：dev 实例运行中脚本直写 → `qink.log` 两次 `external-reload` + 屏幕截图肉眼确认贴纸实时长出「第二条实时验证」（boot 渲染的紧急红 + 实时写入的常规墨绿分区均正确）；装机版 0.4.0 运行中 add→delete 往返 → 两次 `external-reload`（tasks 20→19）+ 数据 SHA **字节级零残留**。`npm test` 82/82 ✅ · `npm run typecheck` 零错误 ✅。
