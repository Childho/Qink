# qink-tasks · AI 直写 Qink

Qink 的数据是一个纯 JSON 文件（`文档\Qink\data.json`）。本 skill 通过配套脚本安全地读写它：Qink 0.4.0+ 运行中会**热重载实时刷新贴纸**；Qink 未运行或为旧版时写入同样安全，只是下次启动才显示。

## 前置

- 脚本用 Node 运行，无第三方依赖。命令都从仓库根目录发起，路径写全：
  `node .agents/skills/qink-tasks/scripts/qink.mjs ...`
- 数据文件找不到时脚本会自动解析系统文档目录；特殊环境可用 `--file=路径` 或环境变量 `QINK_DATA` 指定。

## 命令速查（输出一律 JSON）

| 命令 | 形式 | 说明 |
| --- | --- | --- |
| 查看 | `... qink.mjs read` | 当前目标（含周期是否当前）、任务（含分区 today/rolled/pinned/urgent）、归档计数、全量数据 |
| 加任务 | `... qink.mjs add '[{"text":"写周报","due":"15:30"},{"text":"急事","pinned":true}]'` | 追加进今日任务；`due` 语法 `15` `15:30` `9/30` `明天` `后天`；`pinned` 可选 |
| 勾完成 | `... qink.mjs complete '{"text":"写周报"}'`（或 `{"id":"…"}`，可传数组） | 移入已完成清单（带完成时间） |
| 删任务 | `... qink.mjs delete '{"text":"占位"}' --yes` | **破坏性**：需先向用户确认再加 `--yes` |
| 写目标 | `... qink.mjs goal quarter '发布 1.0'`（month/week 同理；`--clear` 清除） | 季/月/周核心目标，周期键自动按当前周期生成 |
| 替换清单 | `... qink.mjs replace '[{"text":"只有这一件事"}]' --yes` | **破坏性**：整表替换任务列表，需确认 |

## 安全铁律

1. **写前必读**：任何写操作前先 `read`，基于最新状态构造操作（脚本内部也会以文件当前内容为基底，但你要先看清现状再决定改什么）。
2. **追加为默认**：add 自动跳过文本相同的既有任务（报告在 `skippedDuplicate`）；只有用户明确说「替换/清空重来」才用 replace。
3. **两级确认**：add / complete / goal 直接执行；delete / replace 必须先在对话里列出将受影响的任务（用 `read` 的结果点名），用户同意后才加 `--yes` 执行。不加 `--yes` 脚本会以退出码 2 拒绝并列出计划。
4. **如实汇报**：把脚本返回的 report 原样转述给用户——加了什么、跳过了什么重复、哪些没匹配到（notFound）、是否发生了撞车重试（retried）。
5. **失败不硬来**：脚本返回 `ok:false` 时把错误原因告诉用户，不要绕过脚本直接编辑 data.json（会绕开校验、原子写与撞车保护）。

## 边界与语义（写错必显示错乱）

- `createdAt`（今日/滚入分区依据）与 `completedAt` 由脚本按当前时间生成，不要手工指定。
- `dueAt` 语义：**今天=时刻**（`15`、`15:30`，已过的会被拒绝）；**明天起=日期**（`9/30`、`明天`，存当日 0 点）。直写 ISO 格式必须是无时区整秒 `YYYY-MM-DDTHH:mm:00`，且非 0 点时刻只允许今天。
- 目标带周期键，只对当前周期生效；写入即用当前周期覆盖该档（旧周期的残留会被自然替换）。
- skill 不改 settings（窗口位置/形态/置顶等是 Qink 自身状态）。
- 并发撞车：用户正好在 Qink 里编辑（300ms 防抖窗口）时，Qink 的内存态优先，脚本会自动重试一次；两次失败会如实报错，稍后重跑即可。
